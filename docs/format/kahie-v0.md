# `.kahie` file format — version 0.1 (draft)

- **Status:** Draft (P0-13). To be reviewed by the tech lead.
- **Licence of this specification:** same as the project (GPL-3.0-or-later); anyone may write readers and writers.
- **Goal:** a notebook stays readable **without Kahie** (independence principle). A plain ZIP tool and a JSON reader are enough to recover every page's content.

## 1. Container

A `.kahie` file is a **ZIP archive** (deflate or store). Paths use `/`, are UTF-8, and are case-sensitive.

```
notebook.kahie
├── manifest.json          required — what this file is (§2)
├── document.json          required — current state, human-readable (§3)
├── pages/<page-id>.crdt   required — one Loro snapshot per page, full history (§4)
├── library.crdt           optional — section/page tree (Loro), when sections exist
├── assets/<sha256>        optional — images, PDFs, fonts, named by content hash
├── thumbnails/<page-id>.png  optional — derived, may be regenerated
└── preview.pdf            optional — derived rendering of all pages
```

Readers must ignore unknown entries. Writers must not put anything outside these paths except under `x-<vendor>/`.

## 2. `manifest.json`

```json
{
  "format": "kahie",
  "version": "0.1.0",
  "created_by": "Kahie Android 0.1.0",
  "created_at": "2026-11-20T12:00:00Z",
  "notebook": { "id": "nb-1", "title": "Géométrie" },
  "pages": ["page-1", "page-2"],
  "spec": "https://github.com/Heritiana-Ankatso/Kahie/blob/main/docs/format/kahie-v0.md"
}
```

| Field | Required | Meaning |
|---|---|---|
| `format` | yes | Always `"kahie"` |
| `version` | yes | Semantic version of this specification |
| `created_by` | no | Application and version that wrote the file |
| `created_at` | no | RFC 3339 UTC timestamp |
| `notebook` | yes | `id` (stable) and `title` |
| `pages` | yes | Page ids in reading order |
| `spec` | no | URL of this document |

## 3. `document.json`

The current state of every page, validated by [`document.schema.json`](document.schema.json). Example: [`examples/document.json`](examples/document.json) (generated by the `nb-model` test `document_json_example_is_current`, so it always matches the code).

- Coordinates are **page units** (1 unit = 1 CSS pixel at 96 dpi; an A4 page is 794 × 1123).
- A page's `size` (optional, default `a4`) is one of `a3`, `a4`, `a5`, `letter`, each optionally `-landscape` (A3 = 1123 × 1587, A5 = 559 × 794, Letter = 816 × 1056). A custom size is written `<width>x<height>mm` (e.g. `210x99mm`; 50–1000 mm per side, at most one decimal); its page units are millimetres × 96 / 25.4, rounded.
- Colours are `0xRRGGBB` integers.
- `points` of a stroke are the **raw ink**; an `interp` with `show: true` is drawn instead of the ink but never replaces it (ADR-0003).
- Item order in `items` is the drawing order, bottom to top.
- Images reference `assets/<sha256>`.

`document.json` is **derived**: when it disagrees with `pages/*.crdt`, the CRDT data wins. Importers that do not understand CRDT data may rely on `document.json` alone and lose only history.

## 4. Page CRDT snapshots

Each `pages/<page-id>.crdt` is a Loro 1.x snapshot (`ExportMode::Snapshot`) whose layout is documented in `core/crates/nb-model/src/crdt.rs`:

| Root container | Type | Content |
|---|---|---|
| `meta` | map | `id`, `template` |
| `order` | movable list | object ids, bottom to top |
| `objects` | map | object id → map of fields; `deleted: true` marks the trash |

Stroke ink is a binary value in the packed ink encoding v1 (`nb_model::inkcodec`): version byte `1`, varint point count, then three columns (x, y, pressure) of zig-zag delta varints, with x/y in 1/16 page unit and pressure in 1/1024.

## 5. Versioning

- `version` follows semantic versioning. A **minor** bump adds optional fields or entries; a **major** bump may change meaning.
- Readers accept every older version (migration code lives in `nb-store`/`nb-model`) and refuse a newer **major** version with a clear message.
- Before 1.0.0, minor versions may still change; files are migrated on import.

## 6. Relation to on-device storage

On the device each page is a SQLite database (`nb-store`: update log + snapshots). Export compacts each page into `pages/<id>.crdt`, renders `document.json`, copies referenced assets and writes the ZIP. Import does the reverse. The web app's older `.kahie` backups (JSON, Kahie Web v0.1) are recognised by the absence of `manifest.json` and converted on import.

## 7. Open points

- Encryption of exported files (optional password) — not in v0.
- Whether `document.json` should embed rich-text marks once rich text lands (P1-17).
- Tilt and timestamp channels in the ink encoding (reserved for ink encoding v2).
